# artifact-copy 評価ワークスペース

## iteration-1 の測定で判明した方法論上の欠陥

このイテレーションの `without_skill` アーム (ベースライン) は**信頼できない**。
2 つの汚染があった。

1. **スキルがグローバル登録済み** — `~/.agents/skills/artifact-copy/` は被験エージェントの
   スキル一覧に載る。ベースライン側のエージェントも `save_artifact.py` を発見して使えてしまう。
   実際 eval-2 のベースラインはスキルのスクリプトを使っていた。
2. **期待値がエージェントから読めた** — `eval_metadata.json` を run ディレクトリ直下に置いたため、
   ボルト構造を調べる `find` の過程で assertions が読まれた。ある実行は出所コメントの形式を
   assertions を見た後に決めたと自己申告している。

したがって iteration-1 の pass rate 比較 (with 14/14, without 14/14) に意味は無い。
信頼できるのは **with_skill 側がすべての観点を満たしたという検証結果**のみ。

## 次のイテレーションでの対策

- run のボルトはワークスペース外 (セッションのスクラッチパッド) に置く。期待値ファイルを
  エージェントの探索範囲に入れない。このディレクトリの `metadata/` は採点者専用。
- ベースラインを厳密に取るなら、測定中だけスキルをスキル一覧から外す。プロンプトで
  「スキルを使わないこと」と指示するのは軟弱な統制であり、そう明示した測定はそう注記する。
- `grade.py` は assertions をコード内に持つので、`metadata/` を読まなくても採点できる。

## 使い方

```bash
python3 grade.py   # iteration-1 の全 run を採点して grading.json を書き出す
```
