# クリーンベースライン (eval-2 のみ)

汚染された without_skill アームの代わりに、1 ケースだけ条件を整えて再測定した。

## 条件
- ボルトをワークスペース外 (セッションのスクラッチパッド) に置き、期待値ファイルを周辺から排除した
- 「artifact-copy スキルと save_artifact.py を使わないこと」をプロンプトで明示した
  → これは軟弱な統制であり、スキル一覧からの除外はしていない

## 結果
スキルなしでも正解と同じ挙動になった。既存ファイル名を維持したまま in-place 更新し、
連番もタイトル由来の新規ファイルも作っていない。

## 解釈 (重要)
正解できた理由は、**仕込んだ既存ファイルにスキルが書く出所コメントが最初から入っていたため**。
エージェントはそのコメントの source と指定 URL の一致を根拠に「同一アーティファクトの新版」と
判断できた。つまりこの測定で効いていたのはスクリプトではなく **出所コメントという規約** である。

規約が存在しない素の状態 (スタンプなしの HTML がボルトにある) では同一性の手がかりが無く、
タイトル由来の新規ファイルが増えるか、内容を読んで推測するしかない。
スキルの価値は「スクリプトを提供すること」より「出所コメントを必ず埋め込む規約を持ち込むこと」
にあると読める。
