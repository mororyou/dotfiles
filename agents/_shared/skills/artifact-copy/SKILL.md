# アーティファクト HTML の Obsidian 保存

公開したアーティファクトは claude.ai 側にあり、ローカルには残らない。あとから読み返したり
オフラインで開いたりできるように、HTML をボルトへ「そのまま」アーカイブする。

## 前提

| 項目 | 値 |
|---|---|
| 既定ボルト | `/Users/mororyou/Obsidian/Knowledge` |
| 既定の保存先 | `AI/Artifacts/` |
| スキル本体 | 正本は `~/.agents/skills/artifact-copy/`。`~/.claude/skills/artifact-copy` はここへの symlink |
| 保存スクリプト | `~/.agents/skills/artifact-copy/scripts/save_artifact.py`（命名・重複判定・出所記録を担当） |
| 保存形式 | 単一ファイルなら `<名前>.html`、複数ファイル構成なら `<名前>/index.html` |

## ワークフロー

### 1. HTML をローカルに用意する

| 状況 | やること |
|---|---|
| このセッションで公開した | 公開元の HTML がスクラッチパッド等に残っているので、そのパスを使う |
| アーティファクトの URL を渡された | Artifact ツールの `read` に `path: "index.html"` と `out_dir` を渡して取り寄せる（※ハーネス依存、下記） |
| 手元に HTML がある | そのパスを使う |

URL から取り寄せる場合、複数ファイル構成かどうかを `list` の `scope: "files"` で先に確認する。
`index.html` 以外があれば `paths` でまとめて取り寄せ、`--extra-file` で渡す。CSS や JS を取りこぼすと
アーカイブしたページの見た目が崩れるため、ここは省略しない。

URL は `?sk=...` 付きのままでも `--source-url` に渡してよい。共有トークンは
ボルトに焼き込まれないようスクリプト側で除去される。

> [!warning] URL からの取り寄せは Artifact ツールのあるハーネス限定
> `read` / `list` は Claude Code の `Artifact` ツールの機能で、Codex など他のハーネスには存在しない。
> Artifact ツールが使えない環境で URL だけ渡されたら、取り寄せを試みずにユーザーへ
> 「HTML ファイルを手元に用意してほしい」と伝えること。保存スクリプト自体はどのハーネスでも動くので、
> ローカルの HTML さえあれば以降の手順は同じ。

### 2. ファイル名を決める

ファイル名は **1 か月後に Obsidian の検索窓に打ち込む言葉** で決める。
アーティファクトの `<title>` はページの見出しとして気の利いた言い回しになっていることが多く、
そのままでは後から探せない。

> [!example] このボルトでの実例
> `<title>` が「改修は内から外へ」のアーティファクトは、`クリーンアーキテクチャ改修手順.html`
> として保存されている。タイトルは標語、ファイル名は検索語、という使い分け。

- `<title>` がすでに内容を言い当てているなら `--title` を省略する（`<title>` が採用される）
- 標語・比喩・体言止めで内容が読み取れないなら `--title` に内容を表す名詞句を渡す
- どちらとも言い難いときは候補を 1 つ提示して確認する。名前は後から `--rename` で直せる

### 3. スクリプトで保存する

```bash
python3 ~/.agents/skills/artifact-copy/scripts/save_artifact.py save \
  --html /path/to/artifact.html \
  --title "クリーンアーキテクチャ改修手順" \
  --source-url "https://claude.ai/artifact/XXXX"
```

複数ファイル構成の場合:

```bash
python3 ~/.agents/skills/artifact-copy/scripts/save_artifact.py save \
  --html /tmp/dl/index.html \
  --title "売上ダッシュボード試作" \
  --source-url "https://claude.ai/artifact/YYYY" \
  --extra-file "style.css=/tmp/dl/style.css" \
  --extra-file "assets/app.js=/tmp/dl/app.js"
```

### 4. 結果を伝える

スクリプトの 1 行目が結果を表す。これをそのまま鵜呑みにせず、意味を汲んでユーザーに伝える。

| 出力 | 意味 | 伝え方 |
|---|---|---|
| `created` | 新規保存した | 保存先パスを伝える |
| `updated` | 同じ出所の既存ファイルを更新した | 既存の名前を維持して中身を差し替えたことを伝える |
| `renamed` | `--rename` で改名した | 新旧の名前を伝える |
| `unchanged` | 内容が同一なので書き込んでいない | 既に保存済みであることを伝える |
| `duplicate` | 同内容のファイルが別名で存在する | 既存パスを伝え、重複を避けたと伝える |
| `warning` | 同じ出所の保存が複数ある | 整理が必要かもしれないと伝える |
| `rename-skipped` | 改名先が既存だったので改名しなかった | 手動整理が必要と伝える |

## 同じアーティファクトを何度保存しても増えない仕組み

アーティファクトは公開後に更新されることが多い。素朴に書き出すと `名前 (2).html` が積み上がって
ボルトが汚れるため、スクリプトは 2 段階で同一性を判定する。

1. HTML 先頭に `<!-- claude-artifact source="..." saved="..." -->` を埋め込む（描画には影響しない）
2. 保存時、同じ `source` を持つファイルがあればその**名前を維持したまま中身だけ更新**する

2 番目が重要で、ユーザーが後から付け直したファイル名を尊重する。タイトル由来の名前で
新しいファイルを作ってしまうと、せっかく整えた命名が壊れる。

出所コメントが不要なら `--no-stamp` を付けられるが、その場合は内容ハッシュ一致のみが
重複判定の手がかりになり、更新版は別ファイルとして増えていく。

## Obsidian 内で内容を検索したいとき

Obsidian は `.html` を検索やグラフの対象にしない。ファイルエクスプローラーには並ぶが、
クリックすると外部ブラウザで開くだけで、中の文字列は検索に出てこない。

内容まで Obsidian 側で追えるようにしたい場合は、HTML の保存に加えて obsidian スキルで
要約ノートを作り、`[[<名前>.html]]` でリンクする。拡張子まで書くと HTML 側に解決される。
ただしこのボルトの既定の運用は HTML 単体のアーカイブなので、ノートは
ユーザーが検索性を求めたときに追加する。勝手に増やさない。

## 注意

- ボルトは同期される可能性がある。認証情報や社外に出せない値を含むアーティファクトは、保存前に一言確認する
- 保存先を変えたいときは `--dir`（ボルト内相対パス or 絶対パス）と `--vault` で差し替えられる
- 書き込み前に結果だけ見たいときは `--dry-run`、既存を無条件に上書きしたいときは `--force`
- 保存済みの一覧は `save_artifact.py list` で出せる（出所 URL も一緒に表示される）
