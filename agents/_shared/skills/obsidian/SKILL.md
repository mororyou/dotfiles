# Obsidian ノート作成スキル

ユーザーの Obsidian ボルトに、**frontmatter プロパティ・コールアウト・表・Mermaid・wikilink を活かした「リッチで見やすい」ノート**を作る。
目標は「Obsidian のリーディングビューで開いた瞬間に構造が掴め、1 か月後の自分が読んでも価値が残るノート」。

## 前提

| 項目 | 値 |
|---|---|
| 既定ボルト | `/Users/mororyou/Obsidian/Knowledge` |
| 言語 | 日本語（コード・固有名詞は原文のまま） |
| 有効な機能 | プロパティ, タグ, コールアウト, Mermaid, Canvas, Bases（コミュニティプラグインは無し。Dataview 構文は使わない） |
| スキル本体 | 正本は `~/.agents/skills/obsidian/`。`~/.claude/skills/obsidian` と `~/.codex/skills/obsidian` はここへの symlink |
| 生成スクリプト | `~/.agents/skills/obsidian/scripts/obsidian_note.py`（frontmatter 生成・ファイル名サニタイズ・重複回避を担当） |

## ワークフロー

### 1. 作成先を決める

優先順位は「ユーザーの明示指定 > 内容から推定 > ボルト直下」。

- ユーザーが「〜フォルダに」「〜配下に」「`/path/to`」と言ったらそれを使う。ボルト内の相対パス（例: `Engineering/Frontend`）でも絶対パスでもよい。ボルトの外の絶対パスが指定された場合は `--vault` にその親を渡すか、`--dir` に絶対パスを渡す。
- 指定が無ければ既存フォルダの意図から推定する。まず `python3 ~/.agents/skills/obsidian/scripts/obsidian_note.py tree` で現状のフォルダと既存ノート（title / tags）を確認してから決めること。既存ノートの一覧は wikilink 先の候補にもなる。

| フォルダ | 入れるもの |
|---|---|
| `AI/` | LLM・モデル比較・プロンプト・AI ツール全般 |
| `AI/Skills/` | Claude Code スキル・エージェント設計 |
| `Engineering/Frontend/` `Engineering/Backend/` | 技術メモ・設計判断・トラブルシュート |
| `Books/` | 読書メモ |
| `Conferences/` | 勉強会・カンファレンス・登壇メモ |
| `Works/<プロジェクト>/` | 業務メモ（IJU, 1D などプロジェクト別） |

どこにも当てはまらない場合は最も近いフォルダに置き、返答でその判断を一言添える。存在しないフォルダはスクリプトが自動で作る。

### 2. ノートの型を選ぶ

内容に応じて `~/.agents/skills/obsidian/references/templates.md` の型を 1 つ選ぶ。型ごとの見出し構成・frontmatter の `type` 値・推奨コールアウトがまとまっている。

| 型 | `type` | 典型的な依頼 |
|---|---|---|
| 知識・技術メモ | `knowledge` | 調べたこと、概念の整理、比較 |
| 手順・ハウツー | `howto` | セットアップ手順、運用手順 |
| 読書メモ | `book` | 本の要約・学び |
| イベントメモ | `event` | 勉強会・カンファレンス |
| 業務・会議メモ | `work` | 決定事項・TODO・議事録 |
| 判断記録 | `decision` | 設計判断・ADR 的な記録 |

### 3. 本文を書く

`~/.agents/skills/obsidian/references/formatting.md` の記法を使って本文を組む。**構造化の指針**:

- **冒頭に `> [!abstract] 要約` コールアウト**を置き、3 行以内で結論を書く。読む側はまずここで「読む価値があるか」を判断する。
- **見出しには絵文字を 1 つ添える**（`## 📌 ポイント`）。アウトラインペインで並んだときに視覚的な索引になる。
- **比較・一覧は表に**、**手順は番号付きリストに**、**注意点は `> [!warning]`、コツは `> [!tip]`** に。文章のベタ書きで済ませない。
- **関係性・フロー・状態遷移は Mermaid** で描く。4 要素以上の関係を文章で説明しているなら図にする合図。
- **重要語は `==ハイライト==`**、**外部情報は脚注 `[^1]`** で出典を残す。
- **既存ノートへの `[[wikilink]]`** を最低 1 つ入れる。`tree` で見つけたタイトルをそのまま使う（存在しないリンクを量産すると Graph が汚れるので、無ければ将来作るべきノート名を 1〜2 個に絞る）。リンク先の名前は**ファイル名と同じ制約**を受ける。`[[判断: 〜]]` のように `:` `/` `#` `|` `[]` を含む名前は、実際にそのノートを作った時点でサニタイズされてリンクが切れるので、最初から使わない。
- **ユーザーが言っていない情報を足すとき**（候補案・背景説明・参考リンクなど）は、事実として混ぜずに「候補」「補足」「要確認」と分かる形で書く。議事録や判断記録では特に、後から読んだときに「決まったこと」と「AI が足したこと」が区別できることが信頼性に直結する。
- **末尾に `## 🔗 関連` セクション**を置き、wikilink と外部リンクを並べる。
- 長いコードや補足は折りたたみコールアウト `> [!example]-` に入れて本筋を軽くする。

長さの目安: 短い備忘でも要約 + 本文 + 関連の 3 ブロックは維持する。逆に情報が薄いのに見出しだけ増やすと空虚になるので、内容が無いセクションは削る。

### 4. スクリプトで書き出す

本文（frontmatter を含まない Markdown）を一時ファイルに書き、スクリプトに渡す。frontmatter はスクリプトが引数から生成するので本文側には書かない。

```bash
python3 ~/.agents/skills/obsidian/scripts/obsidian_note.py create \
  --title "Qwen3.5 ローカル運用メモ" \
  --dir "AI" \
  --type knowledge \
  --tags ai llm local-llm \
  --aliases "Qwen ローカル" \
  --status growing \
  --body-file /path/to/body.md
```

主なオプション:

| オプション | 意味 |
|---|---|
| `--dir` | 作成先。ボルト内相対パス or 絶対パス。省略時はボルト直下 |
| `--vault` | ボルトのルートを差し替える（別ボルトや検証用ディレクトリ）。`create` / `tree` の前後どちらに置いてもよい |
| `--type` | frontmatter の `type` |
| `--tags` | 複数可。`ai/llm` のようなネストタグも可 |
| `--aliases` | 別名。検索性を上げる |
| `--status` | `draft` / `growing` / `evergreen`（🌱🌿🌳 が付く） |
| `--source` | 出典 URL や書籍名 |
| `--append` | 同名ノートがあれば末尾に追記（日付付きの区切り見出しが入る） |
| `--force` | 同名ノートを上書き |
| `--dry-run` | 書き込まずに完成形を表示 |

同名ノートが存在し `--append` も `--force` も無い場合、スクリプトは `タイトル (2)` のように連番を付ける。既存ノートを育てる意図なら `--append` を使うこと。

### 5. 結果を伝える

返答では、作成したパスと、ノートの構成（何をコールアウト・表・図にしたか）を 2〜3 行で伝える。作成先を推定で決めた場合はその理由を添える。

## ファイル名の決め方

- タイトル = ファイル名（Obsidian の慣習。`[[タイトル]]` でリンクできる）。日本語可。
- 内容が一目で分かる名詞句にする。「メモ」「について」のような情報量の無い語は避ける。
- `/ \ : * ? " < > | # ^ [ ]` はリンクを壊すのでスクリプトが自動で全角や `-` に置換する。
- 日付を入れたい型（会議メモ・イベントメモ）は `2026-09-18 チーム定例` のように **ISO 日付を先頭** に置くとソートが効く。

## 追記・更新の判断

「〜にメモを追加して」「さっきのノートに足して」は新規作成ではなく `--append`。frontmatter の `updated` はスクリプトが今日の日付に更新する。既存ノートの構造を尊重し、末尾に日付見出しを付けて追記する。全体を書き直したいときだけ `--force`。
